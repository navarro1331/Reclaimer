# Runtime observations

Current extensions and outstanding limits appear in the [six-area scope](../verification/SIX_AREA_COMPLETION.md). Earlier fixture observations below retain their named profile scope.

This subsystem is an independently authored implementation of the mechanically observed public request and response contracts. Its reference material is the public contract JSON and the vendor documentation linked below. Runtime code, examples, tests, and this document were written without consulting the earlier implementation or its fixtures.

`lib/runtime.mjs` exports operation handlers and capability metadata. A registered handler identifies available code. A successful, schema-valid result identifies a particular completed observation. Neither establishes complete behavioral parity across providers or applications.

## Browser and V8 transport

`browser-cdp.mjs` implements a bounded JSON command transport over Node's WebSocket API. HTTP discovery uses `/json/version` and `/json/list`. Browser operations attach a separate flattened CDP session to the caller-selected page and detach that session in `finally`. The socket is owned by the request; the browser and its pages are external. Discovery reads target metadata without claiming application identity.

Web inspection accepts HTTP(S) pages. An explicit origin list constrains the selected target, frames, scripts, resources, network observations, and script-source retrieval. Without a supplied list, page inspection uses the selected page's current origin. Electron inspection accepts file-backed page targets. URLs in returned metadata omit transport credentials, query values, and fragments. Endpoint credentials are not written into evidence parameters. The native WebSocket transport does not implement arbitrary authorization headers; an unsupported authenticated transport produces an explicit prerequisite error.

The original metadata reader decodes bounded RFC 8288 Link values from actual selected responses and relative DOM link declarations. Agent-related relations remain page-declared, untrusted hints; declaration URLs are never fetched. Quoted delimiters are handled, while malformed, excessive, and alternate-anchor entries are omitted with an explicit limitation. Outside-policy declarations have no retained destination URL.

WebMCP discovery uses the current document.modelContext.getTools API, with an older testing-API fallback. It selects tools owned by the chosen main Window and preserves actual schemas and annotations. Discovery does not execute tools or infer application approval. The owned fixture separately invokes its own registered tool through the browser API to establish the positive provider path. Declarative registration, cross-origin exposure, and other experimental API versions are not fixture-validated.

The page observer retains DOM structure, optional accessibility text, loaded script metadata and explicitly requested source text, resource metadata, post-attachment requests, optionally requested JSON shapes, console metadata, and storage observations. Body values and storage values are not retained by the page inspection contract. Absence before attachment remains unknown. Text or data sections that were not selected are labeled as policy filtered. Missing domains, event limits, and source budgets remain visible in completeness and limitations.

Precise execution observation uses `Profiler.startPreciseCoverage`, one resetting sample, and explicit stop/disable cleanup. It reports UTF-16 ranges and only marks source bounds verified when retained source text contains the range. It does not infer causal attribution from a request initiator, a loaded source, or a registered event listener. Listener inspection selects one CSS node and releases the owned remote object group after reading handler metadata.

Node inspector observation connects to a selected inspector target, enables the Runtime and Debugger domains, retains bounded script and context metadata, disables its domains, and disconnects. A caller-declared Node/Electron role remains explicitly unverified. Loaded scripts do not imply executed branches, export shapes, IPC, or arguments.

## Local captures and exported sources

HAR inspection parses local JSON and preserves the producer's numeric token spelling separately from JavaScript's numeric representation. The mitmproxy reader implements standard typed netstrings, with byte-range record locations and explicit binary-field representation. Transport authorization and cookie fields, embedded URL credentials, and caller-selected sensitive strings are redacted from reported records and retained binary fields. Both formats leave runtime attribution unknown.

Script export verifies captured source byte counts and digests, creates exclusive hash-named files in the selected directory, and writes a manifest. Producer URLs never become executable filesystem paths. Source lookup checks the physical export directory boundary and the manifest's content digest. Exports support debugger source text and captured browser scenario response bytes.

Import tracing parses exported syntax with Babel and resolves literal import/re-export/dynamic-import specifiers against the explicitly selected importer and import map. Computed specifiers and runtime execution remain unknown. Source-map lookup implements v3 VLQ mappings and embedded indexed sections. It returns the greatest generated position at or before the requested UTF-16 position, including equal-position segments. URL sections are not fetched. Embedded sources remain producer claims, with source authenticity and execution explicitly unknown.

PNG comparison verifies the supplied artifact digest and byte count, decodes bounded noninterlaced eight-bit PNG pixels, and compares RGBA channels. Different dimensions produce a dimension mismatch, rather than a pixel-equivalence claim. Unsupported PNG encodings produce a named error.

## Scenario ownership

Browser scenarios use the installed Playwright core package and a caller-selected executable or target. Launch mode creates its own browser context and terminates its owned browser. Connect mode selects the requested target and disconnects from the external browser. Actions are dispatched individually; their outcome and captured artifacts are retained. The starting origin and explicit navigation destinations define the request interception scope. Secret values are resolved only from explicitly named environment variables, are replaced in retained text, and are never copied into evidence parameters. Screenshots are omitted when explicit secret references might appear in pixels.

The scenario observer retains the selected console, page-error, network, frame, worker, and download families. Response/request bytes and header values require their separate capture selections. Authorization and cookie header values remain redacted. Observed credential strings also scrub selected retained text and byte content, including bodies retained before that header was observed; the cleaned bytes receive new digests. This does not establish universal secret detection. Event selection stops after the selected actions and artifacts; already selected content receives a five-second completion budget. Connection cleanup cannot add events to the capture. Selected popup and data WebSocket lifecycles are captured in owned scenarios; control-frame completeness remains unknown. Page-level CDP WebSocket shape observation is a separate capability: it attributes frames through observed `webSocketCreated` connections, restricts them to the corresponding selected HTTP(S) origin, and reports pre-attachment sockets as unknown.

Electron scenarios use Playwright's Electron launcher with the selected executable and application path, a unique owned profile, and a sparse process environment. Explicit click, wait, reload, crash, and application-event deep-link steps retain actual dispatch outcomes. Detachment, main-process evaluations, and graceful cleanup have local deadlines. Unavailable snapshots remain explicit gaps; empty lists cannot establish absence.

Forced cleanup never trusts a PID reported by application JavaScript. The Windows ownership adapter captures the actual launcher and matching executable child through OS parent metadata, executable paths, and creation times. It pins Process handles and rechecks identity and lineage immediately before one root termination attempt. The Windows terminate helper allows a bounded 120-second physical-exit wait within a 150-second command budget; a Kill call alone cannot establish success. An already-exited captured root can be confirmed without another termination, while an absent launcher cannot authorize killing a still-live root. The fixture rejects a deliberately mismatched creation identity while the owned app remains alive, and verifies actual root exit after graceful close. A separate focused owned fixture proves actual OS-verified forced root termination and launcher exit. The renderer-crash scenario used graceful cleanup. Separate owned quit-prevention and blocked-main scenarios verify the integrated forced cleanup path and actual root exit. Linux ownership support uses /proc identity; the separate X11/AT-SPI UI adapter has the finite owned proof described in the current scope. Unsupported forced-cleanup adapters fail explicitly. Selected Electron IPC hooks observe renderer sends, main-to-renderer delivery and invoke handlers registered after attachment, including result shapes and hook conflicts. Pre-attachment invoke handlers remain unavailable. Preload, native-addon, updater, shell and permission hooks retain their separate limits. Deep links deliver application events; OS protocol registration is not claimed.

## Process and native observations

Each process scenario starts an isolated Node helper with a JSON stdin request and cancellation IPC. The helper uses the installed node-pty-compatible backend to create a real PTY and xterm to render terminal state. The wire field `pty_backend: node-pty` describes that compatible PTY API, while `provider_version` identifies this implementation. The helper process contains native backend resources and exits after the owned PTY target finishes and its result is written. Its temporary directory is selected by the parent context; the deliberately sparse target environment is never used to reconstruct that selection.

Only caller-selected environment entries are passed to the target, plus Windows' required SystemRoot. Evidence stores selected environment names and scope digests, rather than environment values or an ambient environment snapshot. Sensitive input events are redacted before retained output and final rendering. Output is coalesced into one final sanitized render: intermediate display states and precise output chunk order are not claimed. Input, resize, and signal events retain their actual dispatch outcomes. Windows supports termination rather than POSIX signal delivery.

Filesystem observation visits only the explicitly selected paths, does not follow symlinks, and reports count, depth, and hash-budget omissions. File effects with missing digests or partial enumeration stay unknown. Root process sampling is bounded. Detached descendants, full process-tree coverage, network traffic, and loaded-image identity remain unknown. The selected executable digest and stable path metadata are not substituted for loaded-image identity.

The Windows UI helper uses UI Automation for a selected PID/HWND, verifies ownership and launch identity for every snapshot, and captures only that control tree. Invoke, Scroll, and Value patterns implement the caller-listed actions. Unsupported control patterns produce failed steps. Password field values are not read. PrintWindow requests pixels for that exact window; inaccessible or accelerated content produces explicit gaps. No full-desktop screenshot is collected. This adapter leaves the selected window as it stands after the requested actions. macOS and Linux UI adapters are not implemented.

The native-call adapter supports a bring-your-own LLDB executable with Python SB API support, configured through `lldbPath` or a known local installation. It creates a target, supplies explicit launch arguments/environment, installs named breakpoints, observes bounded stops and register/backtrace metadata, and terminates its owned target when the observation limit ends. Missing debugger/Python/platform prerequisites return an unavailable result. Requests beyond the local sixty-second or two-thousand-event limit are rejected rather than silently narrowed. Breakpoint resolution is retained from actual stopped-process observations so module unloading at exit cannot erase an observed location. The Windows x64 fixture uses a privately configured LLDB with working Python SB support, opens an owned compiled PE through the public engine, and proves real registers, backtraces, exit, unresolved-symbol uncertainty, and event-limit cleanup. Objective-C receiver identity, other target triples, and language-level argument semantics remain unknown.

## Validation scope

Synthetic tests exercise a real PTY with an owned Node fixture, selected filesystem changes, HAR token/redaction behavior, typed netstrings and binary fields, an owned headless browser serving only local fixture pages, a selected Node inspector process, and an owned offscreen Windows window. The separate UIA extension also proves actual ValuePattern state change, ScrollPattern increment/decrement, and SHA-valid PrintWindow PNG bytes for that exact window; pixel fidelity is not inferred. Tests never attach to a user's existing app, browser, device, or window.

The browser tests validate discovery, page inspection, precise coverage, nonempty click-listener metadata, actual same-document session events, screenshots and changed-pixel comparison, source export, import/source-map lookup, connected-page replay, and launched replay with form actions, selected storage seeds, request/response bodies, and synthetic credential redaction. They validate actual HTTP Link/DOM agent declarations and native WebMCP registration/discovery plus separate owned-tool invocation. A periodic local request fixture checks that network processing cannot extend the observation window by appending new requests during response decoding. Loopback WebSocket fixtures send real text and binary frames, verify exact selected-origin attribution and outside-policy exclusion, and exercise native ping/pong exchange. CDP exposed no ping/pong control frames in the positive fixture; control-frame observability therefore remains unknown. The Node inspector test validates loaded-script metadata and caller-declared role uncertainty. The process test validates real TTY output, rendering, scoped file effects, environment-value exclusion, unchanged retained terminal comparison with overall unknown process scope, and changed filesystem comparison across two genuine captures. The positive two-capture fixture requires matching normal exits, absent root PIDs and actual created-to-unchanged file hashes/checkpoints within a 15-second owned-test budget; product timeouts are unchanged. Official MCP SDK integration with test-only ordered delivery observes progress, cancels a genuinely started fixture process, and checks that it has exited before the next queued request. The installed SDK 2.3.1 can discard deferred progress callbacks when a coalesced reply removes their handler first. An owned single-write fixture asserts unchanged raw wire order and callbacks [0,1]; a reply-first negative confirms the adapter does not repair incorrect ordering. Unmodified SDK progress delivery remains a consumer limitation. The owned Chrome fixture keeps substantive session assertions and uses a bounded selected-target CDP call for its timer cleanup. Socket/server/browser/profile phases expose deadline failures and retain uncertain profiles. Test-only Windows root cleanup caches OS parent/root creation, executable, lineage and exact profile, checks exit before endpoint mutation, and uses native browser PID plus OS confirmation. Root-only forced cleanup requires pinned/revalidated identity and actual OS exit; a Kill call or debugger disconnect is not success. The Chrome fixture changes leave product provider limits unchanged. The final targeted case proved graceful root exit and profile removal; forced Chrome fallback and arbitrary descendants remain unproved. These tests are bounded examples, not a corpus-wide parity claim. The configured private Electron fixture proves a genuine Electron executable and own file-backed application, target discovery and inspection, reload, application-event deep links, renderer crash, and actual root cleanup. The configured LLDB fixture proves genuine SB launch and machine-call observations for its own PE/PDB. The additional owned Electron fixtures verify IPC send/receive, future invoke-handler shapes, application effects and hook-conflict preservation. These receipts do not establish other Electron versions, arbitrary application compatibility, pre-attachment invoke handlers, Objective-C behavior or whole-process parity. See the scoped coverage receipt for exact completed run counts and remaining prerequisites.
