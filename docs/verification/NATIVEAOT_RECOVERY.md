# NativeAOT recovery evidence

This phase implements an independent, bounded static reader in `lib/native-aot.mjs`, `lib/native-aot-memory.mjs` and `lib/native-aot-types.mjs`. It does not modify the selected executable or a vendor database. `recoverNativeAotDetailed` returns observations; `projectNativeAotRecovery` accepts validated addresses adopted by the caller's owned transient analysis session. Discovery alone leaves public method-table and annotation counts at zero. Generated address labels preserve unknown original names.

## Verified slice

The authored byte suite `test/native-aot-recovery.test.mjs` passed **22/22**. Its fixtures are generated by `test/native-aot-recovery-fixtures.mjs`, independently of any reference-product fixture. Every main positive variant contains three nonempty frozen records and six anchored method tables; an additional plausible header remains uncommitted.

`test/native-aot-recovery-context.test.mjs` passed **8/8** against actual `Context.call` handlers. Each of the four pointer-width/directory variants commits six generated fixed layouts and three distinct instance layouts into the owned session, queries datatypes by address/id/name, and reads exact reconstructed bytes with derived confidence, range/hash provenance and a null source-file offset. The tests reject a file-offset interpretation of derived memory and preserve selected-source hashes. Evidence publication failure, post-staging cancellation/source mutation, an invalid staged DTO and overlapping reconstructed modules leave no new annotations or ledger entries; a prior commitment remains intact where present. Closing the binary clears the transient analysis session.

The fixed method-table header, vtable and interface pointer widths follow the official [.NET 8.0.31 MethodTable declaration](https://github.com/dotnet/runtime/blob/v8.0.31/src/coreclr/nativeaot/Runtime/inc/MethodTable.h). Object-header, component-count and string storage offsets follow the official [object-layout declaration](https://github.com/dotnet/runtime/blob/v8.0.31/src/coreclr/nativeaot/Runtime/ObjectLayout.h). Section identifiers and directory widths were checked against [module-header format facts](https://github.com/dotnet/runtime/blob/v8.0.31/src/coreclr/tools/Common/Internal/Runtime/ModuleHeaders.cs). These sources supplied format facts; the reader and fixtures are newly authored.

## Actual compiler specimen

`test/native-aot-recovery-provider.test.mjs` passed **1/1**, with zero skips when explicitly run with `REAL_RUN_NATIVE_VARIATIONS=1`. It rebuilds only `test/fixtures/native-aot-recovery/RecoveryProof.csproj` and `Program.cs`, using the existing SDK **8.0.425** and private **Microsoft.DotNet.ILCompiler 8.0.31** package cache. The command is an argv-only `dotnet exec` invocation of the explicit SDK's `MSBuild.dll`; package sources are cleared, compiler sharing and node reuse are disabled, and profile/output/temp paths are owned. It also invokes the public load/type/byte handlers and verifies genuine session commitment, exact owned UTF-16 bytes and derived provenance. The generated executable is never run.

Provider fixtures are optional and configured only for tests: `REAL_TEST_EVIDENCE_ROOT` supplies the proof/package root (otherwise `test/provider-fixtures`), and `RECLAIMER_RECOVERY_EVIDENCE` supplies the output root (otherwise repository `.cache/recovery`). Outputs live in that root's `owned-aot-recovery` directory. Production providers are not enabled by these defaults.

## Residual limitations

- Original metadata type/method/field names, NativeFormat reflection-map associations, arbitrary original instance fields and semantic identities are not recovered. Generated labels are explicit.
- Generic composition/definitions, limited/function-pointer method tables, dynamic method tables, optional fields, GC descriptors, finalizer/sealed-slot structures, interface dispatch maps and runtime dispatch behavior remain undecoded. Unsupported instance forms do not become defined layouts.
- Arrays expose bounded component bytes and base extents; rank/bounds semantics and nested reference traversal remain unknown.
- No live memory, runtime allocation, target execution, vendor-database annotation, original IL/decompilation recovery or runtime-validity claim is made.
- Actual compiler proof is one **win-x64 .NET 8.0.31** specimen. Other supported pointer widths/directory variants have authored-byte proof only; other SDK/compiler/platform/version behavior is unverified. No Mac checks occurred.
- Recovery uses little-endian fields and at most 64 recognized headers. Request-wide ceilings are **16 MiB** attempted reconstruction output, **1,000,000** commands including failed streams, **10,000** decoded fixed types, **10,000** frozen instances, **100,000** observed layout fields and **10,000** structural candidates. Individual fixed records permit at most 1,024 virtual slots and 1,024 interfaces. Configuration can lower these ceilings. An incomplete frozen prefix and unanchored structural candidates stay explicit.

Both public contract files remain byte-identical to this phase's starting inputs: `lib/api-contracts.json` SHA256 `66f7c612d12b0771095b3717c193669b86eed3f242f6bdfe4594384c5fc89f29`; `lib/cli-contracts.json` SHA256 `ca942e7ad48933c827a2f6b1f07cc4e23fc531c366c41a1535f8a5642dec1909`. Schema acceptance and handler registration are not claimed as behavioral parity.
