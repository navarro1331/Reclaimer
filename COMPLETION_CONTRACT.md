# Reclaimer completion contract

This contract defines evidence for finishing a scoped Reclaimer delivery.
It does not make every capability, platform or REA behavior complete.
The current scope is NativeAOT identities, Swift declarations, the requested
project documentation and publication of the verified update.

## Acceptance criteria for this delivery

| Criterion | Required evidence |
| --- | --- |
| Compatibility | Byte-identical CLI/MCP contract files; retain 95 CLI commands, 139 operations, six prompts, legacy alias/settings and required wire constants |
| NativeAOT identities | Owned byte and compiler fixtures prove supported explicit metadata/map/fixup/layout/hash associations, custom/nested names, generated aliases and unbound/conflict suppression |
| Swift declarations | Owned compiler/modulewrap output proves 14 normalized and 38 raw rows with nondefault required/convenience/override/final facts, supported inheritance and schema dispositions |
| Integrity and atomicity | Owned source mutation, malformed input, aggregate-capacity and late-cancellation cases preserve prior evidence and avoid partial recovery publication |
| Public transports | Actual CLI and official stdio MCP checks preserve existing envelopes, selectors and exact exported/imported evidence identities |
| Strict validation | Complete build and full test summary from one identified run; required native/Swift/runtime fixtures; zero failures, skips, cancellations, todos or timeout; successful schema-validated calls for 139/139 operations |
| Source binding | Frozen implementation/fixture/configuration hashes still match after the run; publication bytes bind to the verified checkpoint and explicit portable-document substitutions |
| Documentation | Requested root documents and three ADRs contain useful current content; Markdown links resolve; status and changelog match completed evidence |
| Notices and ownership | All 57 application notice files retain inventory hashes; required private tool notices stay with those excluded tools; authored-file audit has no unexpected direct source matches |
| Publication | Sanitized snapshot build and focused tests pass; a normal update of the named public branch is pushed; fetched commit, parent, tree and every manifest blob match; private history stays excluded |
| Limits | Mac checks remain pending and unsupported recovery, platform and parity branches remain documented |

The full run establishes execution of its test cases. Successful operation counts
describe observed calls, not comprehensive branch coverage. Hashes describe byte
consistency, not authenticity, permission or legal provenance.

## Broader product completion

Full functional equivalence requires an agreed capability matrix and independent
behavior comparison on the same owned artifacts. Each claimed branch needs a
positive observation, relevant negative controls, resource/cancellation proof and
explicit provider/platform scope. Missing tools or environments stay pending.

Generic NativeAOT identities, arbitrary original layouts, code-entry relationships,
broader Swift serialized formats and real Mac runtime/provider behavior cannot be
closed by registering a handler or validating an empty response.

## Evidence and change control

Keep raw run output, frozen hashes, compiler receipts, failed/interrupted attempts
and publication receipts locally. Publish portable scope reports and fixture
sources. Refresh [PROJECT_STATUS.md](PROJECT_STATUS.md) from the accepted run;
use the repository history and local fetched-remote receipt for the published SHA.

The operator owns scope and compatibility decisions. This document records
delivery acceptance criteria; it adds no runtime identity, approval or execution gate.
Changes to public contracts, distribution terms or hosted execution are separate
work. See the [architecture decisions](decisions/ADR-001-architecture.md).
