# Reclaimer completion contract

This contract defines evidence for finishing a scoped Reclaimer delivery.
It does not make every capability, platform or REA behavior complete.
The current scope is the finite six-area NativeAOT, Swift, artifact-format,
JavaScript, runtime/provider and session-reporting extension, retained transaction
and cancellation regressions, local packaging/contained worker verification,
documentation and publication. The [current matrix](docs/verification/SIX_AREA_COMPLETION.md)
records remaining branches and reasons. Mac/IDA and client/live worker activation
remain pending.

The full run establishes execution of its test cases. Successful operation counts
describe observed calls, not comprehensive branch coverage. Hashes describe byte
consistency, not authenticity, permission or legal provenance.

## Six-area acceptance

The current [six-area scope](docs/verification/SIX_AREA_COMPLETION.md) requires fresh owned NativeAOT, Swift, JVM/codec and isolated Linux UI producer receipts in the strict run; trace/freshness, session lifecycle, comparison, provider uncertainty and format boundary cases; and unchanged contract/notice/source hashes. Provider prerequisites are required rather than silently skipped. A public snapshot additionally builds and passes its portable focused suite. Remaining branches and their reasons must stay visible after acceptance.

## Broader product completion

Full functional equivalence requires an agreed capability matrix and independent
behavior comparison on the same owned artifacts. Each claimed branch needs a
positive observation, relevant negative controls, resource/cancellation proof and
explicit provider/platform scope. Missing tools or environments stay pending.

The finite supported generic identities, recorded offsets/entrypoints and exact
Swift formats do not close every generic/layout/code or language branch. Arbitrary
original layouts, unqualified formats and real Mac/IDA provider behavior cannot be
closed by registering a handler or validating an empty response. Local package
and Docker success do not establish client or live worker activation.

## Evidence and change control

Keep raw run output, frozen hashes, compiler receipts, failed/interrupted attempts
and publication receipts locally. Publish portable scope reports and fixture
sources. Refresh [PROJECT_STATUS.md](PROJECT_STATUS.md) from the accepted run;
use the repository history and local fetched-remote receipt for the published SHA.

The operator owns scope and compatibility decisions. This document records
delivery acceptance criteria; it adds no runtime identity, approval or execution gate.
Changes to public contracts, distribution terms or hosted execution are separate
work. See the [architecture decisions](decisions/ADR-001-architecture.md).
